# Vanilla JS Daily Todo

HTML, CSS, Vanilla JS, Web Storage API만 사용해 만든 일간/주간 Todo 앱입니다.

## 실행 방법

별도 빌드 과정이나 패키지 설치가 필요 없습니다.

1. `index.html` 파일을 브라우저에서 엽니다.
2. Todo를 추가, 수정, 완료, 삭제합니다.
3. 브라우저 개발자 도구의 Application 탭에서 `daily-todo-items` localStorage 값을 확인합니다.

## 구현 기능

- Todo CRUD
  - 빈 입력값은 저장하지 않고 안내 메시지를 표시합니다.
  - Todo 추가, 인라인 수정, 완료 체크, 삭제가 가능합니다.
  - 완료된 Todo는 취소선과 흐린 색상으로 구분합니다.
- 상태 필터
  - 전체, 진행 중, 완료 탭으로 현재 선택 날짜의 Todo를 필터링합니다.
  - Todo를 추가해도 현재 필터 상태가 유지됩니다.
- 일간 뷰
  - 오늘 날짜와 선택 날짜를 표시합니다.
  - 이전 날짜, 다음 날짜, 오늘 이동 버튼으로 날짜를 이동합니다.
  - 이전 월, 다음 월, 이전 년, 다음 년 버튼과 연도/월 입력으로 날짜를 빠르게 변경할 수 있습니다.
  - Todo 생성 시 현재 선택된 날짜가 자동 저장됩니다.
- 주간 뷰
  - 월요일부터 일요일까지 날짜를 표시합니다.
  - 이전 주, 다음 주 버튼으로 주차를 이동합니다.
  - 날짜별 Todo 개수를 표시하고, 오늘 날짜와 선택 날짜를 시각적으로 구분합니다.
- 전체 Todo 보기
  - 날짜별 보기와 전체 Todo 보기를 전환할 수 있습니다.
  - 전체 Todo 보기에서는 모든 날짜의 Todo를 한 목록에 표시합니다.
- 정렬
  - 날짜별 보기와 전체 Todo 보기 모두에서 정렬할 수 있습니다.
  - 날짜 빠른순, 날짜 늦은순, 최근 추가순, 오래된 추가순으로 정렬할 수 있습니다.
- 페이징
  - 현재 보기, 필터, 정렬 결과를 페이지 단위로 나누어 표시합니다.
  - 이전, 다음 버튼으로 페이지를 이동할 수 있습니다.
  - 페이지당 5개, 10개, 20개 표시를 선택할 수 있습니다.
- localStorage 연동
  - Todo 변경사항을 `JSON.stringify`로 저장합니다.
  - 페이지 로드 시 `JSON.parse`로 기존 데이터를 복원합니다.

## 작업 기록

### 1. 파일 구조 결정

과제 조건의 기본 구조에 맞춰 `index.html`, `style.css`, `app.js`, `README.md`를 사용했습니다. 라이브러리와 프레임워크는 사용하지 않았고, 브라우저 기본 DOM API와 localStorage만 사용했습니다.

### 2. 데이터 구조 결정

Todo는 아래 형태의 객체 배열로 관리했습니다.

```js
{
  id: 'todo-...',
  text: '할 일',
  completed: false,
  date: '2026-06-03',
  createdAt: 'ISO 날짜 문자열',
  updatedAt: 'ISO 날짜 문자열'
}
```

날짜별 관리를 위해 각 Todo에 `date` 값을 저장했습니다. 날짜는 비교와 저장이 쉬운 `YYYY-MM-DD` 문자열로 통일했습니다.

### 3. CRUD 구현 과정

처음에는 수정 기능을 `prompt`로 처리할 수도 있었지만, 사용 흐름을 더 명확하게 보여주기 위해 인라인 수정 폼을 선택했습니다. 수정 버튼을 누르면 해당 Todo 항목이 입력창, 저장, 취소 버튼으로 바뀌며 빈 값 저장은 차단합니다.

삭제는 현재 배열에서 해당 `id`를 제외하는 방식으로 처리했습니다. 완료 처리는 `completed` 값을 반전시키고, 렌더링 단계에서 완료 스타일을 적용했습니다.

### 4. 필터와 날짜 상태 관리

현재 필터는 `currentFilter`, 선택 날짜는 `selectedDate` 상태로 분리했습니다. 새 Todo 추가 후에도 `currentFilter`를 변경하지 않기 때문에 탭 전환 상태가 유지됩니다. 날짜 이동 시에는 수정 중인 항목을 닫고 선택 날짜에 맞는 Todo만 다시 렌더링하도록 했습니다.

### 5. 주간 뷰 구현 과정

주간 뷰는 선택 날짜가 포함된 주의 월요일을 기준으로 계산했습니다. JavaScript의 `getDay()`는 일요일을 `0`으로 반환하므로, 일요일인 경우 6일을 빼고 그 외에는 `dayIndex - 1`일을 빼 월요일을 구했습니다.

각 날짜의 Todo 개수는 전체 Todo 배열에서 `date`가 같은 항목을 세어 표시했습니다. 날짜 버튼 클릭 시 `selectedDate`를 해당 날짜로 바꾸고 일간 목록을 다시 렌더링합니다.

### 6. localStorage 문제 해결

localStorage에는 문자열만 저장할 수 있으므로 Todo 배열 저장 시 `JSON.stringify`를 사용했습니다. 불러올 때는 `JSON.parse`를 사용하되, 저장된 값이 깨졌거나 배열이 아닌 경우 앱이 멈추지 않도록 빈 배열로 복구했습니다.

### 7. UI 의사 결정

메인 컬러는 과제 조건의 `#672be0`을 기준으로 버튼, 활성 탭, 선택 날짜에 적용했습니다. 미니멀한 생산성 앱 느낌을 위해 흰색 카드, 옅은 회색 배경, 제한적인 보조 색상만 사용했습니다. 모바일에서도 입력 폼과 Todo 항목이 겹치지 않도록 레이아웃을 세로로 전환했습니다.

### 8. 전체 Todo 보기 추가

추가 요청에 따라 날짜별로 제한된 목록만 보는 방식 외에 전체 Todo를 한 번에 보는 모드를 추가했습니다. 기존 `selectedDate`는 Todo 생성 날짜를 결정하는 상태로 유지하고, 목록 표시만 `currentView` 값에 따라 분기했습니다.

전체 보기에서는 서로 다른 날짜의 Todo가 섞이므로 각 항목에 날짜 배지를 표시했습니다. 정렬 기준은 `currentSort`로 분리해 날짜 빠른순, 날짜 늦은순, 최근 추가순을 선택할 수 있게 했습니다. 날짜가 같은 Todo는 최근 추가된 항목이 위에 오도록 보조 정렬을 적용했습니다.

### 9. 페이징 추가

추가 요청에 따라 Todo 목록에 페이징을 추가했습니다. 페이징은 원본 Todo 배열이 아니라 현재 보기 모드, 상태 필터, 정렬이 모두 적용된 결과를 기준으로 계산합니다. 그래서 전체 보기에서 정렬을 바꾸거나 완료 필터를 적용해도 해당 결과 안에서만 페이지가 나뉩니다.

페이지 상태는 `currentPage`, 페이지당 개수는 `pageSize`로 분리했습니다. 날짜, 주차, 보기 모드, 상태 필터, 정렬, 페이지당 개수가 바뀌면 1페이지로 돌아가도록 처리했습니다. 삭제나 완료 처리로 현재 페이지의 항목 수가 줄어드는 경우에는 전체 페이지 수를 다시 계산해 빈 페이지에 머무르지 않도록 보정했습니다.

### 10. 날짜별 보기 정렬 지원

추가 요청에 따라 전체 Todo 보기에서만 활성화되어 있던 정렬 제한을 제거했습니다. 이제 날짜별 보기에서도 같은 정렬 선택 박스를 사용할 수 있습니다.

날짜별 보기에서는 모든 Todo가 같은 날짜를 가지므로 날짜 빠른순과 날짜 늦은순은 결과 차이가 거의 없습니다. 대신 같은 날짜 안의 정렬 기준이 명확히 보이도록 최근 추가순과 오래된 추가순을 모두 지원하도록 정렬 옵션을 확장했습니다.

### 11. 월/년도 빠른 변경 추가

추가 요청에 따라 선택 날짜를 일 단위로만 이동하지 않고 월/년도 단위로도 빠르게 바꿀 수 있도록 날짜 패널을 확장했습니다. 이전 월, 다음 월, 이전 년, 다음 년 버튼을 추가했고, 연도 입력과 월 선택으로 원하는 월로 바로 이동할 수 있게 했습니다.

선택 날짜 상태는 기존 `selectedDate` 하나를 계속 사용했습니다. 그래서 월/년도 변경 후에도 Todo 생성 날짜, 주간 뷰, 날짜별 목록, 페이징이 같은 기준으로 동작합니다.

31일에서 2월처럼 대상 월에 같은 일이 없는 경우가 있어 `createClampedDateKey` 함수를 추가했습니다. 이 함수는 이동하려는 월의 마지막 날짜를 계산해 선택 일을 자동으로 보정합니다.

- `index.html`에서 `style.css`, `app.js`가 정상 연결되어 있는지 확인했습니다.
- 전체 Todo 보기 추가 후 `node --check app.js`를 다시 실행해 문법 오류가 없는지 확인했습니다.
- 페이징 추가 후 `node --check app.js`를 다시 실행해 문법 오류가 없는지 확인했습니다.
- 날짜별 보기 정렬 지원 후 `node --check app.js`를 다시 실행해 문법 오류가 없는지 확인했습니다.
- 월/년도 빠른 변경 추가 후 `node --check app.js`를 다시 실행해 문법 오류가 없는지 확인했습니다.
- Playwright와 Puppeteer는 현재 환경에 설치되어 있지 않아 브라우저 자동 클릭 테스트는 진행하지 못했습니다. 대신 DOM 이벤트 연결, localStorage 저장 키, 날짜 계산 흐름을 코드 기준으로 재점검했습니다.
