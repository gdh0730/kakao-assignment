## 과제 목표
이번 과제를 통해 Vanilla JS 기반 Todo 앱을 직접 구현하면서 HTML/CSS/JS의 역할을 나누고, DOM 조작과 이벤트 핸들링, localStorage 저장 흐름을 이해하는 것을 목표로 함.

- HTML/CSS/JS의 역할과 구조를 이해하기
- DOM 조작과 이벤트 핸들링을 직접 경험하기
- 로컬스토리지를 활용해 데이터를 저장하고 불러오기
- AI 프롬프팅을 활용해 코드를 작성하고, 생성된 코드를 이해하고 수정하기

## AI 활용 내역
AI를 활용해 구현하거나 수정한 내용을 기록해요.
단순히 어떤 프롬프트를 썼는지보다, 어떤 결과를 받았고 어떻게 수정했는지를 중심으로 작성해요.

### Todo CRUD 구현하기
- AI 활용 내용 :
HTML, CSS, Vanilla JS만 사용한다는 조건에 맞춰 기본 Todo 앱 구조를 생성했어요. 입력창과 추가 버튼, Todo 목록, 수정/완료/삭제 버튼, 빈 입력값 안내 메시지, 완료 Todo 취소선 처리가 포함된 코드를 받음.
- 직접 수정한 부분 :
수정 기능은 `prompt` 방식이 아니라 Todo 항목 안에서 바로 입력값을 바꿀 수 있는 인라인 수정 폼으로 구현. 저장/취소 버튼을 추가하고, 수정값이 비어 있으면 안내 메시지를 표시.
- 수정 이유 :
실제 Todo 앱처럼 목록 안에서 바로 수정하는 흐름이 더 자연스럽고, 사용자가 어떤 항목을 수정 중인지 명확하게 볼 수 있다고 판단.

### 상태별 필터링 구현하기
- AI 활용 내용 :
전체, 진행 중, 완료 필터 탭을 만들고 현재 선택된 필터에 따라 Todo 목록을 다시 렌더링하는 구조를 만듦.
- 직접 수정한 부분 :
`currentFilter` 상태를 따로 두고, Todo를 추가하거나 날짜를 이동해도 현재 필터 상태가 유지되도록 했다.
- 수정 이유 :
필터 탭을 선택한 뒤 새 Todo를 추가했을 때 필터가 초기화되면 사용 흐름이 끊기기 때문에, 필터 상태를 독립적으로 관리하는 편이 더 적절하다고 생각함.

### Todo 일간 뷰 구현하기
- AI 활용 내용 :
오늘 날짜 표시, 이전/다음 날짜 이동, 선택 날짜에 해당하는 Todo만 보여주는 기능을 구현.
- 직접 수정한 부분 :
Todo 데이터에 `date` 값을 `YYYY-MM-DD` 형식으로 저장하고, 날짜 비교와 localStorage 저장에 같은 값을 사용하도록 통일함.
- 수정 이유 :
날짜를 문자열로 통일하면 날짜별 필터링과 JSON 저장/복원이 단순해지고, 다른 날짜의 Todo와 섞이지 않게 관리할 수 있기 때문에.

### 로컬스토리지 연동하기
- AI 활용 내용 :
Todo 배열을 `JSON.stringify`로 localStorage에 저장하고, 앱 시작 시 `JSON.parse`로 불러오는 코드를 작성.
- 직접 수정한 부분 :
저장된 값이 없거나 JSON 파싱에 실패하거나 배열이 아닌 값이 들어온 경우 빈 배열로 복구하도록 예외 처리를 추가함.
- 수정 이유 :
localStorage 데이터가 깨져도 앱 전체가 멈추지 않고 정상적으로 다시 사용할 수 있게 하기 위해서.

### Todo 주간 뷰 구현하기
- AI 활용 내용 :
월요일부터 일요일까지의 주간 날짜 목록, 이전 주/다음 주 이동 버튼, 날짜별 Todo 개수 표시 기능을 구현.
- 직접 수정한 부분 :
JavaScript의 `getDay()`에서 일요일이 `0`으로 나오는 점을 고려해, 선택 날짜가 속한 주의 월요일을 직접 계산하는 함수를 작성함.
- 수정 이유 :
과제 요구사항이 월요일부터 일요일까지의 주간 뷰였기 때문에, 브라우저 기본 요일 값과 요구사항 기준을 맞춰야 했다.

### 전체 Todo 보기 기능
- AI 활용 내용 :
날짜별 보기와 전체 Todo 보기를 전환하는 UI를 추가하고, 전체 보기에서는 모든 날짜의 Todo를 한 번에 표시하도록 구현.
- 직접 수정한 부분 :
전체 보기에서 서로 다른 날짜의 Todo가 섞여 보이므로 각 항목에 날짜 배지를 표시하도록 했다.
- 수정 이유 :
전체 Todo를 한 목록에서 볼 때 어떤 날짜의 할 일인지 바로 확인할 수 있어야 목록을 이해하기 쉽다고 판단.

### Todo 정렬 기능
- AI 활용 내용 :
날짜 빠른순, 날짜 늦은순, 최근 추가순 정렬 기능을 추가.
- 직접 수정한 부분 :
이후 날짜별 보기에서도 정렬이 가능해야 한다는 요구에 맞춰 정렬 select를 항상 활성화했고, 같은 날짜 안에서도 차이를 볼 수 있도록 오래된 추가순 옵션을 추가함.
- 수정 이유 :
날짜별 보기에서는 모든 Todo가 같은 날짜라 날짜순 정렬 차이가 거의 없기 때문에, 생성 시각 기준 정렬 옵션이 필요했다.

### Todo 페이징 기능
- AI 활용 내용 :
Todo 목록 아래에 페이지당 개수 선택, 이전/다음 버튼, 현재 페이지 정보를 표시하는 페이징 UI를 추가.
- 직접 수정한 부분 :
페이징은 원본 Todo 배열이 아니라 현재 보기 모드, 상태 필터, 정렬이 모두 적용된 결과를 기준으로 계산하도록 했다.
- 수정 이유 :
필터나 정렬을 적용한 뒤에도 사용자가 보고 있는 결과 안에서만 페이지가 나뉘어야 기대한 방식으로 동작하기 때문에.

### 월별/년도별 날짜 빠른 변경 기능
- AI 활용 내용 :
이전 월, 다음 월, 이전 년, 다음 년 버튼과 연도 입력, 월 선택 UI를 추가.
- 직접 수정한 부분 :
31일에서 2월로 이동하는 경우처럼 대상 월에 같은 날짜가 없을 때 해당 월의 마지막 날짜로 자동 보정하는 `createClampedDateKey` 함수를 추가했다.
- 수정 이유 :
월/년도 이동 시 잘못된 날짜가 만들어지거나 예상과 다른 달로 넘어가는 문제를 방지하기 위해서.

## 구현하면서 고민한 점
구현 과정에서 막혔던 부분이나 고민했던 내용, 해결 방법을 자유롭게 작성해요.

- 고민한 점 :
Todo를 날짜별로 분리하면서도 전체 Todo 보기에서는 모든 날짜의 Todo를 한 번에 보여줘야 함.
- 해결 방법 :
Todo 데이터에는 항상 `date` 값을 저장하고, 목록을 렌더링할 때 `currentView` 상태에 따라 날짜 필터를 적용하거나 건너뛰도록 분기했다.

- 고민한 점 :
필터, 정렬, 페이징이 동시에 적용될 때 어떤 순서로 처리해야 하는지.
- 해결 방법 :
먼저 보기 모드와 상태 필터를 적용하고, 그 결과를 정렬한 뒤 마지막에 현재 페이지 범위만 잘라서 렌더링하도록 순서를 정했다.

- 고민한 점 :
월/년도 이동 시 31일처럼 일부 월에 존재하지 않는 날짜를 어떻게 처리할지.
- 해결 방법 :
대상 월의 마지막 날짜를 계산해서 선택 일을 자동 보정하는 방식으로 해결.

## 과제 회고
과제를 마치고 느낀 점, 아쉬운 점, 다음에 개선하고 싶은 점을 자유롭게 작성해요.

- 다음에 시도해볼 것 :
Todo 검색, 중요도 표시, 드래그 앤 드롭 순서 변경, 브라우저 자동 테스트를 추가해 앱의 완성도와 안정성을 더 높이고 싶다.
