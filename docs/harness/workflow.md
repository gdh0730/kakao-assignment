# Workflow

## 1. 계획
- 사용자 요구사항과 현재 구현 범위를 확인한다.
- 변경 범위, 유지할 호환성, 검증 방법을 먼저 문서화한다.

## 2. 설계
- 상태, 데이터 schema, 컴포넌트 경계, localStorage 흐름을 정한다.
- 장기적으로 영향을 주는 결정은 ADR에 기록한다.

## 3. 구현
- UI 컴포넌트와 순수 유틸을 분리한다.
- 날짜/정렬/페이징처럼 오류가 나기 쉬운 로직은 `src/lib`에 둔다.

## 4. 테스트
- 순수 유틸은 단위 테스트로 검증한다.
- 사용자 흐름은 Testing Library로 검증한다.
- 변경 후 `npm run test:run`과 `npm run build`를 실행한다.

## 5. 검증과 회고
- README, ISSUE, harness 문서가 실제 구현과 일치하는지 확인한다.
- 문제 해결 과정과 직접 수정한 이유는 `prompt-log.md` 또는 ISSUE에 남긴다.
